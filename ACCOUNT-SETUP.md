# Необязательные аккаунты и синхронизация

Код находится в `api/account.js` и `sync.js`. Задачи и теория работают без входа. Регистрация становится доступной только после подключения постоянного хранилища.

## Подключение к существующему проекту Vercel

1. Открой существующий проект `tfkp-trainer` в Vercel.
2. Подключи отдельную базу Upstash Redis через Storage / Marketplace либо уже существующую базу с REST API. Перед созданием проверь выбранный тариф у провайдера.
3. В серверных Environment Variables проекта должны быть `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`. Также поддерживается пара `KV_REST_API_URL` / `KV_REST_API_TOKEN`, которую может создать интеграция Vercel.
4. Используй токен с правом записи. Не добавляй переменные с префиксом `NEXT_PUBLIC_`, не записывай токен в репозиторий и не вставляй его в чат.
5. Подключи переменные для Production и выполни новый Deploy. Для отдельной проверки Preview используй отдельную тестовую базу; не связывай её с данными пользователей Production.

Без этих переменных `/api/account` возвращает `configured: false`. Окно входа сообщает, что хранилище ещё не подключено. При ошибке сервиса сайт оставляет прогресс в браузере и показывает состояние отправки.

## Поведение

- Ник: 3–32 латинские или русские буквы, цифры, точки, дефисы, подчёркивания. Регистр не различается.
- Пароль: 10–128 символов. Восстановление по почте не предусмотрено; интерфейс предупреждает об этом до регистрации.
- Создание аккаунта переносит текущие отметки. При входе в существующий аккаунт прежний прогресс без входа сохраняется отдельно. Его можно добавить кнопкой; уже существующие отметки аккаунта при этом не заменяются.
- Общие данные: статусы и повторение задач, прочитанные темы, выученные/повторяемые карточки. Настройки фильтров и список выбранных вопросов остаются настройками браузера.
- Отметки отправляются после изменения, при возвращении на вкладку и периодически в активной вкладке. Кнопка позволяет запросить синхронизацию сразу.
- Очередь неотправленных изменений сохраняется локально. Явное снятие отметки сохраняет запись сброса, поэтому старая копия другого устройства не восстанавливает её.
- Выход завершает текущий серверный сеанс и возвращает местный прогресс без входа. Сеансы на остальных устройствах остаются действительными.

## Серверные меры

Соль для каждого пароля и scrypt `N=131072, r=8, p=1`; случайные серверные сеансы; cookie `__Host-tfkp_session` с `HttpOnly`, `Secure`, `SameSite=Lax`. Cookie не читается клиентским JavaScript. Запись требует проверки Origin и CSRF. Сеанс определяет владельца данных; переданный клиентом ID сверяется с ним. Чужие отметки не выдаются по нику или ID.

Поддерживаются только опубликованные 500 задач, 77 разделов и 172 карточки. Проверяются типы значений и размер запросов. Попытки входа ограничиваются в постоянном хранилище. Данные обновляются одним атомарным Lua-скриптом; повторный запрос с тем же идентификатором операции не меняет результат.

## Проверки

`npm run test:account` проверяет API и клиент: пароль, два сеанса, изоляцию пользователей, Origin/CSRF, снятие отметок, устаревшие запросы, повторную отправку, очередь без связи, восстановление после перезагрузки и выход.

После подключения живого хранилища нужна отдельная проверка:

1. Создай тестовый аккаунт в одном браузере; отметь одну задачу и карточку теории.
2. Войди тем же ником во втором браузере. Проверь обе отметки.
3. Во втором браузере верни задачу в нерешённые; в первом нажми «Синхронизировать сейчас» и проверь статус.
4. Проверь отключение сети, новую отметку, перезагрузку и повторное подключение.
5. Выйди; проверь возврат местной копии без входа и изоляцию другого аккаунта.

Локальные тесты не являются подтверждением подключения рабочей базы на Vercel.
